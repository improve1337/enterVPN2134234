# Заявки, оплата и статистика VPN

Документ описывает то, что видно в админке вокруг продаж: переключатель оплаты,
заявки на подписку и статистику по VPN. Актуально на 8 ноября 2026.

---

## 1. Зачем это

Пока платёжка не подключена, продавать «в один клик» нельзя. Поэтому оплату можно
**выключить** — тогда вместо покупки пользователь оставляет заявку, а админ выдаёт
доступ вручную. Когда платёжка появится, оплату включают кнопкой, и всё работает
как раньше (покупка + автоматическая выдача).

---

## 2. Переключатель оплаты

«🛠 Админка» → «💳 Оплата» → кнопка «🟢 Включить оплату» / «🔴 Выключить оплату».

| Состояние | Что видит пользователь |
|---|---|
| **Выключена** (по умолчанию) | «💎 Тарифы» → кнопки «📨 Оставить заявку» |
| **Включена** | «💎 Тарифы» → кнопки покупки (как раньше) |

Состояние хранится в таблице `settings` (ключ `payments_enabled`), переживает
перезапуск. Если оплата выключена, а пользователь всё же нажмёт кнопку покупки
(старое сообщение в чате) — бот ответит, что оплата выключена, и предложит заявку.

---

## 3. Заявки на подписку

### Как подаёт пользователь

«💎 Тарифы» → выбирает тариф → заявка уходит админам. Пользователь видит
«📨 Заявка отправлена». Повторная заявка не создаётся: пока предыдущая не
закрыта, бот отвечает «Заявка уже отправлена».

### Как обрабатывает админ

«🛠 Админка» → «📨 Заявки (N)» — список новых заявок. На каждую две кнопки:

- **✅** — выдать доступ: бот оформляет подписку по тарифу из заявки
  (через Marzban), заводит ключ и отправляет пользователю ссылку;
- **❌** — отклонить: пользователю уходит уведомление.

Заявка хранится в таблице `requests` со статусами `pending` / `approved` /
`rejected`. Одобрить или отклонить можно только заявку в статусе `pending` —
повторное нажатие вернёт «Заявка уже обработана».

### Уведомления

- о новой заявке бот пишет **всем админам** в личку;
- об одобрении/отклонении — пользователю.

## 4. Статистика VPN

«🛠 Админка» → «📊 Статистика». Кроме данных бота (пользователи, подписки,
заказы) показывается блок по Marzban:

| Строка | Откуда |
|---|---|
| Пользователей | `total` из `GET /api/users` |
| Активных | пользователи со статусом `active` |
| Онлайн (5 мин) | у кого `online_at` свежее 5 минут, с юзернеймами |
| Трафик всего | сумма `used_traffic` по всем пользователям |

Нюансы:

- Marzban считает «онлайн» за **24 часа** (`online_users` в `/api/system`) — для
  «активных подключений» это слишком широко, поэтому бот берёт окно 5 минут;
- `online_at` Marzban отдаёт без часового пояса и с шестью знаками после точки —
  бот трактует такие значения как UTC;
- если панель недоступна, блок пишет «нет данных» и статистика бота всё равно
  показывается (ошибка Marzban не ломает экран).

## 5. Код

| Файл | Что |
|---|---|
| `src/services/settings.ts` | переключатель `payments_enabled` |
| `src/services/requests.ts` | создание, список, одобрение и отклонение заявок |
| `src/services/provision.ts` | `marzbanOverview()` — сводка для статистики |
| `src/db.ts` | таблицы `settings` и `requests` |
| `src/ui/keyboards.ts` | `plansKeyboard(paymentsEnabled)`, `requestsKeyboard`, `paymentsKeyboard` |
| `src/ui/texts.ts` | тексты заявок, оплаты и блок VPN в статистике |
| `src/bot.ts` | колбэки `req:`, `req:ok:`, `req:no:`, `adm:requests`, `adm:payments*` |
| `tests/requests.test.ts` | 9 тестов: переключатель и жизненный цикл заявки |

## 6. Как проверить

```bash
cd bot
npm run typecheck
npm test          # 51 тест, из них 9 — заявки и оплата
```

В Telegram (mock-режим или бой):

1. «🛠 Админка» → «💳 Оплата» → убедиться, что выключена.
2. «💎 Тарифы» → «📨 Оставить заявку» → админам приходит уведомление.
3. «🛠 Админка» → «📨 Заявки» → «✅» → пользователю приходит ссылка-подписка.
4. «📊 Статистика» → видно пользователей VPN, онлайн и суммарный трафик.
5. Включить оплату → «💎 Тарифы» снова показывает кнопки покупки.
